# 今日の危険度 — 公開の手順（オーナー用）と今回の変更

## 今回のコード変更（承認不要の部分）
- 基準（星の点数表・しきい値・注記の文言・状態の文言・収集の期間）は `lib/resolute/risk-policy.ts` の1か所。弁護士の確認後は、ここだけ直す。
- 画面の出し分け: 公開前=「準備中です」／調べて何も無かった日=「今日は、気にするニュースはありません」／失敗=「ニュースを更新できていません」／オーナーが止めた=「公開を停止」。
- 朝7時の確認ジョブ（resolute-rizel-daily-review）が、作った一覧を `risk_days` に保存する（公開はされない。公開は下の2つのスイッチが両方入るまで止まる）。
  - 「何も無かった日」と記録するのは、Stock News API の読み取りが有効で、取りこぼしの恐れが無いときだけ。無効なら記録せず、準備中→（朝の時間帯を過ぎたら）失敗と表示する。
- 候補の拾い方: 見出しの下方ワードを追加（急落・暴落・下振れ・供給制約・予想を上回る 等）。検索の期間を「当日のJST」から「前回の朝以降（月曜は週末ぶん）」に変更。日付だけの記事も、その日付が期間内なら対象。
- 変えていないもの: 証拠の原文一致、新しい数字の禁止、strict JSON、月の費用上限。
- `analystUpdates` は出典URLが公開されないため、候補にできない（URLが必須）。`marketUpdates` はAI下方リスクの話題ではないため対象外。

## 公開のスイッチを入れる手順（本番の変更なので、毎回オーナーの承認が必要）

2. （Claude）承認後、Railway で resolute-api と resolute-rizel-daily-review を再デプロイする。
3. （オーナー）アプリの「resolute/review」→「実際の接続状態」で、保存済みの一覧が見えることを確認する（オーナーだけに見える）。
4. （オーナー承認のうえ Claude）Railway の resolute-api に変数 `RESOLUTE_RISK_PUBLISH_APPROVED=true` を追加し、再デプロイする。
5. （オーナー）管理画面（resolute/news/owner）で、オーナー用スイッチ（risk_control.enabled）をオンにする。両方そろった時点で公開される。
6. 戻すときは、スイッチをオフにする（即時に「公開を停止」になる）。

## 追加（市場全体のニュース）
- 危険度の対象は、個別銘柄だけでなく、ハイテク株を揺るがす市場全体のニュース（金利・関税・輸出規制・大幅な売りなど）。
- Stock News API の「一般の市場ニュース」（`/api/v1/category?section=general`）を、22銘柄の取得に加えて読む。追加の変数や鍵は不要（止めたいときだけ `RESOLUTE_REPORT_MARKET_LANE=false`）。
- 候補の条件: 見出しに市場全体の話題と下方の言葉が両方ある記事。最終判断は、これまでどおり原文一致の検証つきのAI判定。
- 「何も無かった日」の記録は、2つの取得先が両方読めて、取得ページが期間の開始より前まで届いたときだけ。
- どちらかの取得に失敗すると全体を失敗にする（誤って静かな日にしない）。

### 毎日公開されていなかった理由（11/21 時点の本番）
- 公開の2つのスイッチが入っていない。resolute-api に `RESOLUTE_RISK_PUBLISH_APPROVED` が無く、利用者には「準備中です」と出る（ログインしていない人にはログイン画面）。
- 朝の確認ジョブ（resolute-rizel-daily-review、`0 22 * * 0-4`＝平日7:00）は動いているが、温度計（resolute-thermometer-refresh、`0 23 * * 1-5`＝8:00）より1時間早い。前の晩の米国の終値の動きがまだ無いので、全部の記事が「市場の反応待ち」になり、★が付かない。あとで★を埋める処理（react）を動かすサービスも無い。
- 11/20 は新しい順の3件がすべて検証で落ち、日全体が失敗（NO_VERIFIED_OUTPUT）。代わりの候補を試していなかった。日本語の「50億ドル」は原文の「$5 billion」と数字が一致しないので、正しい要約でも落ちていた。

### 今回の変更
- 朝の実行を8時台（JST）に移す（`RISK_POLICY.runHourJst`）。Railway の cron は `20 23 * * 0-4`（平日8:20）。温度計のあとなので、前の米国の取引時間中に出たニュースは、その朝のうちに★が付く。
- 候補は「終値の動きがもう分かっている記事」を先に選ぶ（同じ組の中は新しい順）。
- 検証で落ちた記事は、次の候補で置き換える。AIの要約は1日最大5件まで（書き直しを含めて最大10回）。全部落ちたら今までどおり日全体を失敗にし、何も公開しない。
- 同じ実行の中で、前の日までの「市場の反応待ち」の記事にも★を埋める（新しいサービスは不要）。ここで失敗しても、その日の処理は止めない。
- 日本語の文：金額は原文のまま書かせ、サービスが桁をずらして正確に「億ドル」「万ドル」に直す。「米ドル」は「ドル」。閉じ括弧の直後に「。」「、」を付けない。原文の金額を日本語の単位に直した数字だけは、原文の数字として数える。
- 日付：AIには発表時刻に加えて東京とニューヨークの日付を渡し、その日付の数字も原文の数字として数える（米国の夕方の記事を「翌日」と書いて落ちていた分）。
- 検証で落ちた理由を、記事IDと固定の理由コード（not-publishable / new-number / japanese-amount / shape）だけでログに残す。本文は残さない。
- 見出しの下方ワードに bearish / bear market を追加。
- RIZELの一言の選択は、★が付いた記事だけでおこなう（今までは全部「市場の反応待ち」だったので、一度も選ばれていなかった）。文章は今までどおり非公開の保存先（承認済み90組）から選び、リポジトリには入れない。公開は保留のまま。
- ★の決め方・注記・締めの質問・禁止表現のチェック・公開スイッチは変えていない。
