# 今日の危険度 — 公開の手順（オーナー用）と今回の変更

## 今回のコード変更（承認不要の部分）
- 基準（星の点数表・しきい値・注記の文言・状態の文言・収集の期間）は `lib/resolute/risk-policy.ts` の1か所。弁護士の確認後は、ここだけ直す。
- 画面の出し分け: 公開前=「準備中です」／調べて何も無かった日=「今日は、気にするニュースはありません」／失敗=「ニュースを更新できていません」／オーナーが止めた=「公開を停止」。
- 朝7時の確認ジョブ（resolute-rizel-daily-review）が、作った一覧を `risk_days` に保存する（公開はされない。公開は下の2つのスイッチが両方入るまで止まる）。
  - 「何も無かった日」と記録するのは、Stock News API の読み取りが有効で、取りこぼしの恐れが無いときだけ。無効なら記録せず、準備中→（朝の時間帯を過ぎたら）失敗と表示する。
- 候補の拾い方: 見出しの下方ワードを追加（急落・暴落・下振れ・供給制約・予想を上回る 等）。検索の期間を「当日のJST」から「前回の朝以降（月曜は週末ぶん）」に変更。日付だけの記事も、その日付が期間内なら対象。
- 変えていないもの: 証拠の原文一致、新しい数字の禁止、strict JSON、月の費用上限。
- `analystUpdates` は出典URLが公開されないため、候補にできない（URLが必須）。`marketUpdates` はAI下方リスクの話題ではないため対象外。

## 公開のスイッチを入れる手順（本番の変更なので、毎回オーナーの承認が必要）
1. （オーナー）このPRの内容と基準の文言に問題がないか確認し、承認する。
2. （Claude）承認後、Railway で resolute-api と resolute-rizel-daily-review を再デプロイする。
3. （オーナー）アプリの「resolute/review」→「実際の接続状態」で、保存済みの一覧が見えることを確認する（オーナーだけに見える）。
4. （オーナー承認のうえ Claude）Railway の resolute-api に変数 `RESOLUTE_RISK_PUBLISH_APPROVED=true` を追加し、再デプロイする。
5. （オーナー）管理画面（resolute/news/owner）で、オーナー用スイッチ（risk_control.enabled）をオンにする。両方そろった時点で公開される。
6. 戻すときは、スイッチをオフにする（即時に「公開を停止」になる）。
