# Tech Phase Research：実装内容と公開までの条件

更新日：2026年9月19日

## AI関連20銘柄への拡張

公式資料の取得先をMU・NBISから20銘柄へ拡張しました。`lib/research/providers.json` で会社名、分野、公式URL、取得形式、ホストとURL範囲を管理し、取得処理と画面で共用します。

- 半導体：MU、NVDA、AMD、AVGO、ARM、TSM、ASML、MRVL。
- ネットワーク：ANET、CRDO。AIクラウド：NBIS、CRWV。
- 電力・冷却：VRT、GEV。サーバー：DELL。AIソフトウェア：PLTR。
- 大手クラウド：MSFT、AMZN、GOOGL、ORCL。

公式RSS / Atomの読み取りを追加しました。プラグイン候補も確認しましたが、今回の収集に適した追加接続は選ばず、既存の取得処理に標準ライブラリで実装しています。新たな有料サービスは契約していません。

`/research/intake` は20銘柄を表示し、一覧成功・確認必要・未検証を分けます。分野別の絞り込み、会社名検索、銘柄カードから資料への移動、20件単位のページ切り替えを追加しました。各社の公式発表やブログにはAI以外の話題・過去分も含まれます。取得対象の会社が20社になったという意味で、20社のニュース全件を取得できたという意味ではありません。

会社別の決算比較・リサーチページはMU・NBISの2社です。他社の自動要約、数値抽出、影響分析、速報の会員配信はまだ接続していません。取得成功が商用再配信の許諾を意味するものでもありません。

20銘柄すべてに `/research/companies/[ticker]` の銘柄ページを追加しました。MU・NBISは照合済みの数値比較ページを維持し、残る18社は公式一覧の取得状況、登録資料、本文取得数、エラー、検知した公式資料を銘柄ごとに表示します。銘柄ページ上部の選択欄で20社を切り替えられ、取得状況画面の各カードからも移動できます。

18社のページには「公式発表の検知→原文取得→前回比較」の進捗を表示します。数値比較が未作成の段階を明記し、取得済みを分析済みとして表示しません。WHAT CHANGED? の完成版は、発表日、対象期間、会計基準、数値定義を照合した会社から順に追加します。

取り込みのPythonテスト14件、画面ロジックのNodeテスト6件で、RSS、Atom、壊れたXML、外部リンクの除外、分野別抽出、最新取得結果による対応状況の集計を確認しています。

## 今回の成果物

既存プロジェクトに `/research` を追加しました。元の速度測定ページは `/` に保持しています。

公式発表を使った過去事例6件を収録しています。

- NBIS：Palantirとの提携。発表された事実と、未開示の収益貢献を区別。
- NBIS：2026年Q2決算。グループ売上とAIクラウドARRを区別。
- NBIS：契約電力の目標。稼働済み容量と区別。
- MU：2026年度Q3決算。GAAP売上・粗利益率を同じ基準の前四半期と比較。
- NBIS：Q1決算を比較の起点として追加。営業損失と投資評価益を区別。
- NBIS：Q2のATMによる株式売却。調達済みと未使用枠を区別。

`/research/companies/NBIS` と `/research/companies/MU` に銘柄ページを追加しました。

- 各4指標を前四半期と比較。両時点の値、会計基準、対象、期間、原文リンクを表示。
- NBISのARR比較はQ1詳細値$1.92Bを使用し、Q2の丸められた公表値からの概算と明示。
- 営業損失の拡大は金額差で表示。負の比較元から誤解を招く成長率を作らない。
- 同じ対象期間の会社目標を発表日ごとに記録。「4GW超→5GW」から厳密な増加率を作らない。
- MUのQ4売上見通しは$49–51B。実績未収録と表示し、達成・未達を判定しない。
- 確認項目、原文、発表日順の履歴、履歴の絞り込みを実装。日英の選択をページ間で共有。

これは収録した資料を比較する機能です。会員画面への自動更新・自動判定・編集者の承認画面は未実装です。編集用の手動取得・資料確認履歴は以下のコマンドで管理できるようにしました。

### 公式資料の取り込み準備

`scripts/research/monitor.py` を追加しました。Python標準ライブラリのみで、公式一覧のリンク取得、資料取得、ハッシュによる重複・応答変更検出、確認待ち・採用・保留・却下の記録を行います。使用手順は `scripts/research/README.md` にあります。

- 新規取得は確認待ち。既に判断した資料でも応答が変われば再確認待ちに戻ります。
- 取得失敗、未取得、古いハッシュでの判断を拒否。担当者・理由・日時と過去の判断を記録します。
- 一覧からリンクを抽出できない場合は異常として記録し、「新着なし」にしません。
- 新規候補の発表日は未確認のまま保持し、初回検知日を発表日にしません。
- HTML装飾だけでも変更検知される可能性があるため、応答変更を財務情報の訂正と判定しません。
- 生の本文や編集者情報を公開リポジトリに追加せず、採用操作から会員ページへ自動公開もしません。
- ローカルのSQLiteを使用。常時監視、永続ホストへの設置、バックアップ、要約のレビュー画面、訂正本文の差分表示は未実装です。

追加の自動テスト8項目が成功。NBISの公式一覧を実際に取得し、初回20件の発表リンクを検出しました（過去分を含む、最初の一覧ページのみ）。

実取得ではNBISの既存5資料（PDF4件・提携発表1件）に成功しました。MUはIR一覧・既存発表がHTTP 403でしたが、公式本体のニュース一覧 `https://www.micron.com/about/press/news` から発表リンク11件を取得できました。リンク先の本文は追加で試した1件も403のため未解決です。今回のコマンド実行は単発で、定期実行を設定していません。

### 取得状況を確認する画面

`/research/intake` に、実際の取得記録から作った閲覧用の画面を追加しました。

- 一覧取得と本文・PDF取得の成否を分けて表示。
- 資料名・URLの検索、銘柄・取得状態・編集状態の絞り込み、該当なしと解除、原文リンク、資料ごとの履歴表示。
- 原文の発表日が不明なら未確認。初回検知日時や取得試行日時はJSTと明示。
- 保存時点の記録であることと出力日時を明示し、常時監視中とは表示しない。
- 公開側には担当者名・判断理由・本文・例外の詳細メッセージを出力しない。
- 承認・公開操作や編集者認証は未実装。SQLiteから出力した記録を閲覧するプレビュー。

取り込みのPythonテスト10件、表示用のNodeテスト4件、追加コードのESLint、Next.jsビルド・型検査が成功しています。

日本語／英語切替、検索、銘柄・分野の絞り込み、詳細表示、指標一覧、記事のブラウザー内保存を実装しています。保存の端末間同期は未実装です。

各事実に公式原文へのリンクを付け、事実・分析／解釈・未確認事項・次の確認点を分けています。資料の発表日と照合日も分けています。過去の発表を今日の速報に見せる表示はしていません。

新しい有料サービスの契約は行っていません。ただし本番運用全体が無料になるという意味ではありません。

## 信頼性について実装したこと

指標には名称、値、単位、通貨、会計基準、対象会社／事業、期間、期末日、実績／見通し／年換算指標の区分、資料IDを持たせています。

比較時に定義が違うものを拒否し、ゼロ・マイナスの比較元から紛らわしい成長率を作らず、粗利益率の変化はパーセントポイントで計算します。資料リンクの欠落、不正な日付、無効な数値などはビルドで検出します。

これは構造と比較の誤りを防ぐ仕組みです。要約の全内容が正しいことを保証するものではありません。今回の要約は資料を参照して用意した検証例であり、自動要約システムは未実装です。

## 問い合わせの返答待ちでも進める順序

### 1. 会員が使う画面を実際に確認する

確認用URLで日英切替、検索、保存、数値の区分を検証しました。次はスマートフォン実機と利用者による読解の確認です。最初に「何が変わったか」を理解でき、根拠まで迷わずたどれることを合格条件にします。

### 2. 良いニュース以外も検証する

今回、NBISの営業損失拡大とATMによる資金調達・希薄化を追加しました。設備稼働の遅延、ガイダンス下方修正、発表内容の訂正は未収録です。数字が正しくても結論が強すぎる要約を見つけるため、事実と解釈を別々に評価します。

### 3. 更新・訂正を管理する仕組みを作る

資料取得→数値抽出→整合性確認→レビュー→公開の流れを実装します。根拠が足りない場合は保留し、訂正時は前の内容と訂正理由を残します。現在のv1表示は初版の表示のみで、自動の履歴管理は未実装です。

### 4. 接続後に速度と抜け漏れを測る

資料の発表時刻、初めて取得できた時刻、処理完了時刻、画面に出た時刻を区別します。分からない時刻を推定で埋めません。「10秒以内」は実際のイベントで検証する目標であり、達成済みの仕様ではありません。
