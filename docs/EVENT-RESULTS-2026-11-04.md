# 大きな出来事の結果の自動取得(2026-11-04)

決算・指標は数字を読む仕組みがあるが、選挙のような「数字ではない大きな出来事」は、人が気づくまで載らなかった(米中間選挙、11/4)。
監視サービスが、報道機関の公開フィードを読み、**2社以上が同じ結果を報じたとき**に「発表済みの結果」へ自動で載せる。

## 仕組み(`scripts/research/event_results.py`、監視する出来事は `event_watches.json`)
1. 監視の期間(`from`〜`until`)のあいだだけ、5分おきに各社のフィードを読む。期間外は動かない(15分おきに確認するだけ)。
2. 見出しが**当確の形**のときだけ数える: 政党 + 勝つ動詞 + 議院が近くにある(例: 「Democrats win the House」)。
   次は数えない: 「could / poll / odds / if / lose / need …」などのぼかし、「Senate seat」「House race」のような1議席・1選挙区の話、別の政党が間に入る文、「White House」。
3. **発行元が別々の2社以上**が、期間内に同じ結果を報じたら採用する。
4. 同じ議院で両方の政党が「勝った」と報じられたら、**載せず保留**(`conflict`)。
5. 日本語・英語の文は、`event_watches.json` に書いた定型文。AIは書かない。**議席数などの数字は載せない**。
6. 載せる内容: 結果の一文、報じた社の名前とリンク(複数)、「認定は数週間かかる」という注意。
7. 運営者は、結果欄の「この結果を取り下げる」で取り下げられる。取り下げた結果は二度と載らない。

## 設定
- 新しい出来事は `event_watches.json` の `watches` に足す(`claims` = 判定する主張、`combine` = まとめ文、`noteJa/En` = 注意書き)。
- フィードの一覧は `feeds`。つながらない社は、運営者の確認用に状態が残る(`GET /admin/event-results` の `feeds`)。

## API
- 公開: 監視サービスの `/news` の `eventResults`(サイトは `/api/research/news` 経由で読む)。
- 運営者: `GET /admin/event-results`(結果・保留・フィード状態)、`POST /admin/event-results/withdraw {id}`(取り下げ)。サイト側は `/api/research/event-results`(運営者のみ)。

## いまの限界
- 実際の各社フィードへの接続は、監視サービス(Railway)に出して初めて確かめられる(開発環境からは外部のニュースサイトに届かない)。つながらない社があれば、状態に出る。
- 対象は、いまは米中間選挙の議会の多数のみ。FOMC会見などは、`watches` に足していく。
- 手で足した結果の欄(`economicResults`)は、同じidの自動の結果があるとそちらに置き換わる。取り下げても、手で足した欄は残る。
