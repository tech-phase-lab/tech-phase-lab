# RESOLUTE ルール診断の組み込み

Claude提供の `resolute-logic.zip` 最新版（README: 2026-10-10、SHA-256 `6beaa30589839dc0a88bf93e7a51f5c21d21ecf0b1f6282534c704bba46eb50e`）を元に実装。

- `/resolute`: 日英30問、10タイプ、7枚のルールカード、回答別アドバイス、保存。
- `/resolute/simulation`: 保存済み計画を読み込む下落・急騰の試算。入力は保存しない。
- `diagnosis.ts`: Claudeの分類・アドバイス。金額計算は既存 `plan-calculation.ts` に集約。
- `diagnosis-questions-ja.ts`: 添付の参考HTMLから移植した質問・選択肢・入力情報。
- `diagnosis-copy.ts`: 英語の全質問・選択肢・10タイプ・23アドバイス・結果文言。
- `diagnosis-form.ts`: 分岐・入力検証・回答とPlanの変換。質問の金額帯は円のため、英語表示でもJPY。USD計画を円と解釈して上書きしない。
- `plan-client.ts`: 同一originのGET/PUT。401/403/409/429/503と通信失敗を区別し、書込を自動再送しない。

## 更新 — 2026-10-12 ChatGPT

- q01を `first / 1to3 / 3to5 / 5to7 / 7to10 / 10plus` に更新。旧 `3plus` は受付しない。本番計画DBが未導入の段階での確定仕様反映であり、既存回答の推測変換はしない。
- q25に `unknown`、q26に `b5` を追加。数値欄は入力を選んだ場合だけ表示。q06の入力選択は「ある（金額を入力する）」と表示する。
- q25未確定、または基準金額不明のとき、選択したbuyModeを保ったまま `buyLines: []` を保存できる。数字や0円のラインを補完しない。
- `firstDropPct?: number | null` をPlanに追加。診断画面は常に送る。予算不明でラインを作れなくてもcustomの1段階目を失わない。既存形式は引き続き読める。値は0.1〜99.9、小数1桁。具体的なラインがある場合は先頭dropPctと一致必須。
- 複数段階のcustom幅は最終段階が99.9%を超えない範囲で検証し、無断で丸めたり段階を削ったりしない。
- タイプ10種は回答から画面で再計算する。既存4値のruleTypeへ独自対応付けを作らず、診断保存時は参考値 `undecided`。サーバーはタイプ分類をしない。
- 添付のアドバイス条件を2点補正。q28/q29の選択式停止条件があるとき「条件なし」と判定しない。「50%超」という回答だけで50%超の上限違反を断定しない。タイプの採点・優先順と日本語の説明本文は変更しない。
- API成功とrevision更新を確認するまでシミュレーション導線を出さない。競合時に自動上書きせず、通信失敗時も再送前に読込を要求する。
- 回答・自由記述は保存前にはReactのメモリだけ。localStorage・URL・ログ・メールへ出さない。アカウント切替時に破棄する。表示言語は既存設定を読み、画面内切替は設定を書き換えない。
- `simulate.ts` は添付の純粋関数。USD保存計画のセントは呼出時にドルへ換算し、表示も通貨を維持する。許容額nullを0円の許容額と表示しない。

## 確認方法と本番条件

`npm test` に添付の診断テスト23件・シミュレーション12件と統合テストを組み込んだ。金額計算の境界・null・小数、日英選択肢とAPI契約、分岐、未確定ライン、保存失敗・競合を検証する。

本番の計画APIは削除履歴の独立保存・復元接続等の条件を満たすまで503のまま。画面実装は本番の保存完了を意味しない。今回、実DBのmigration・writer・本番有効化・Railway設定・メール送信は行わない。添付の税金・アラート・メールモジュールは今回の組込対象外で、未検証を維持する。
